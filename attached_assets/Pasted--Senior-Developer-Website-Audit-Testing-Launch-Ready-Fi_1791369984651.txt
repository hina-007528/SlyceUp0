# Senior Developer Website Audit, Testing & Launch-Ready Fixes

Act as a **Senior Frontend Engineer, UI/UX Engineer, Responsive Design Specialist, and QA Engineer**. Your task is to thoroughly audit, test, and fix my existing website until it meets professional, launch-ready standards.

## Client's Feedback — Every Point Must Be Addressed

The client said:

> "I need someone to build a launch ready website and not this. This is not responsive, no proper scroll experience, does not match the text layout, width is way off and Hina, I am looking for a more senior developer and you seems to not have that experience."

Treat every point in this feedback as a specific issue that must be investigated, corrected, and retested.

### 1. Audit Before Making Changes

* Inspect the entire existing project, including components, CSS, fonts, assets, layout, and responsive breakpoints.
* Review my latest uploaded Figma desktop and mobile screenshots.
* Use the Figma design and its provided specifications as the source of truth.
* Identify the actual causes of visual and functional problems before modifying code.
* Preserve working functionality and avoid unnecessary rewrites.

### 2. Fix Responsive Design

Test the website at these viewport widths:

320, 360, 375, 393, 414, 430, 480, 600, 768, 820, 900, 1024, 1100, 1280, 1366, 1440, 1536, 1600, and 1920 pixels.

Check every section, navbar, heading, paragraph, form, button, image, background element, and footer.

Fix:

* Horizontal scrolling and overflow.
* Text clipping and overlapping elements.
* Broken layouts between mobile and desktop.
* Incorrect spacing and alignment.
* Oversized or undersized content.
* Images and backgrounds that stretch or crop incorrectly.
* Navigation that breaks at intermediate widths.
* Fixed heights and absolute positioning that cause layout failures.

Do not test only one desktop and one mobile size. Make sure intermediate screen sizes work properly.

### 3. Match Figma Typography and Text Layout

Compare the actual rendered website against my uploaded Figma screenshots.

Verify and correct:

* Font family and whether the font is actually loaded.
* Font size and weight.
* Line height and letter spacing.
* Text color and opacity.
* Text container width and maximum width.
* Alignment and spacing between text blocks.
* Line breaks and heading wrapping.
* Desktop and mobile typography differences.

Use the exact Figma CSS values I provided wherever applicable. Do not guess or substitute fonts, sizes, or colors without a reason.

The text should occupy the same visual space and follow the same line structure as Figma, while adapting correctly to smaller screens.

### 4. Fix Incorrect Website Width

Investigate why the client says the width is way off.

Check the overall page width, maximum container width, horizontal padding, navbar width, hero content width, paragraph width, form width, section alignment, and margins.

Use a consistent container system based on the Figma measurements. Remove conflicting widths, unnecessary fixed dimensions, arbitrary margins, and layout hacks.

The website should preserve Figma's proportions and alignment at the reference viewport sizes.

### 5. Fix Scrolling and Section Flow

Test the entire page from top to bottom on desktop, tablet, and mobile.

Ensure:

* Natural vertical scrolling.
* Correct section order and spacing.
* No accidental horizontal scroll.
* No sections overlapping.
* No content hidden behind a sticky navbar.
* No broken fixed or sticky elements.
* No abrupt or confusing transitions between sections.
* No unnecessary large blank spaces.
* No page sections trapped inside incorrectly sized containers.
* No scroll-related layout shifts.

Keep the website in normal document flow wherever possible. Do not fake the experience using one fixed-height screen.

If smooth scrolling or animations are part of the intended design, implement them carefully without interfering with normal browser scrolling, keyboard navigation, or accessibility.

### 6. Reproduce the Figma Background Accurately

The website background must visually match the uploaded Figma reference as closely as possible.

Inspect all visible background details, including gradients, shapes, colors, decorative elements, images, shadows, opacity, blur, layering, position, scale, and cropping.

Recreate the background with CSS, SVG, HTML, and individual assets where appropriate. Do not replace a detailed Figma background with a generic gradient or a flattened screenshot.

Use the corresponding desktop and mobile Figma layouts as separate visual references. Ensure the background does not stretch, disappear, overflow, or cover text at different screen sizes.

### 7. Test Every Interactive Element

Check:

* Navbar links and mobile menu.
* Sticky navigation.
* CTA buttons.
* Email input and validation.
* Form submission and success/error states.
* Links and navigation destinations.
* Interactive step indicators.
* Any animations or other existing interactions.

Do not leave decorative buttons pretending to work. Preserve existing integrations and connect functionality correctly where the project already supports it. Do not invent successful form submissions or backend functionality.

### 8. Improve Code Quality

Refactor only where necessary to achieve a reliable implementation.

Remove unnecessary duplicated CSS, conflicting media queries, unused styles, excessive `!important`, brittle negative margins, and arbitrary positioning hacks.

Use reusable components, consistent design tokens, maintainable responsive CSS, semantic HTML, and accessible controls.

Do not introduce unnecessary dependencies or break existing project functionality.

### 9. Perform Real Visual QA

Use browser rendering, screenshots, and available testing tools to compare the implementation against the Figma references.

Perform separate checks for:

* Desktop Figma match.
* Mobile Figma match.
* Tablet and intermediate responsiveness.
* Typography and text wrapping.
* Container widths and spacing.
* Background composition.
* Navbar and CTA.
* Form dimensions and behavior.
* Section transitions and scrolling.
* Console errors and runtime failures.

Fix the issues discovered and repeat the tests. Do not simply inspect the code and assume the visual result is correct.

### 10. Final Production Checks

Run the project's available build, lint, type checks, and automated tests.

Check browser console errors, broken assets, missing fonts, failed requests, and obvious accessibility problems. Verify loading behavior and ensure the website remains usable on touch devices and with keyboard navigation.

Do not claim that a test passed unless it was actually run. Clearly report any tests or checks that could not be performed.

## Final Acceptance Criteria

The work is complete only when:

1. The website closely matches the Figma desktop and mobile designs.
2. The background, typography, text wrapping, widths, and spacing are accurate.
3. All tested viewport widths have appropriate layouts.
4. Scrolling and sticky navigation behave correctly.
5. Interactive elements work as intended.
6. No known critical visual, responsive, or functional issues remain.
7. Available build and quality checks pass.
8. The code is maintainable and suitable for deployment.

**Work directly in the existing project. Audit, implement, render, compare, test, fix, and retest. Do not stop after producing a checklist or making superficial CSS changes.**

At the end, provide a concise report containing:

* Issues discovered.
* Changes implemented.
* Viewport sizes actually tested.
* Build and test results.
* Remaining issues or limitations.
* Any deployment steps still required.

The goal is to resolve the client's feedback through measurable improvements, not merely to claim that the website is professional or launch-ready.
